# HerLens 3 分钟演示脚本

**演示目标：**让观众在 3 分钟内看到一条结论如何回到原文和计算口径，以及数据不足时系统如何拒绝过度结论。

**演示前准备：**

- 使用 `npm run dev` 或预先构建的静态页，不依赖现场模型请求。
- 视口使用 1366×768 或 1440×900，预先打开「样本库」。
- 不打开私有原文、`.env`、后台截图或本地绝对路径。
- 开场即说明公开页为“原创虚构演示”，不把示例数字当成真实业务成绩。

## 时间轴

| 时间 | 操作 | 讲解要点 |
| --- | --- | --- |
| 0:00–0:20 | 展示样本库顶部的样本范围和数据状态 | “HerLens 不预测爆款。它先问标题承诺了什么，正文有没有支持，可比指标又能说到哪一步。这 4 篇都是虚构夹具。” |
| 0:20–0:40 | 在作品清单中指出文本覆盖、权限、指标和审核列，打开 `HL-024` | “全文、仅开篇、仅标题导语会得到不同的可判断范围；不把缺失写成零。” |
| 0:40–1:10 | 在作品剖面点击“情绪承诺”证据，再点击结尾证据 | “每个实质标签有值、理由、证据和审核状态。侧栏给出字段、段落、版本和 Unicode 偏移；后端要求引文与规范化原文精确匹配。” |
| 1:10–1:35 | 把一个标签改为不同值，指出“待更新”，然后点击重算 | “人工可接受、修订或驳回模型候选。修订会让统计和报告过期，重算会生成新修订版本，避免界面还展示旧结论。” |
| 1:35–2:05 | 打开对比分析，指出标签频数、作品级原始点和 CTR 口径 | “数字不由模型手算。CTR 是同定义、同渠道、同窗口的 `sum(clicks)/sum(impressions)`，不是单篇百分比的平均。” |
| 2:05–2:25 | 展开 SQL / 查询明细和排除原因 | “查询保留参数、样本数、缺失数和来源快照。曝光缺失、窗口重叠或口径不一致时，它会拒绝混合。” |
| 2:25–2:50 | 打开研究备忘录，展开一条发现的证据和局限 | “建议固定包含观察、证据、适用范围、替代解释、下一步验证和判断标准。最多三条，数据不足时允许没有建议。” |
| 2:50–3:00 | 回到顶部数据标识或导出入口 | “这个项目要证明的是：一个发现可以一路追到原文和 SQL，并说清下一步如何验证。” |

## 如果还有 30 秒

打开仅开篇样本，展示结尾为“未提供／不足以判断”；或打开缺曝光样本，展示系统没有用阅读量伪造 CTR 分母。这比展示更多装饰性图表更能说明产品取舍。

## 高频追问的一句话回答

- **“为什么不做爆款评分？”** 现有小样本与描述性指标无法支持稳定预测，先做可复核特征和可验证假设。
- **“引文对得上就说明标签对吗？”** 不是；精确匹配只防捏造，语义支持仍需手册和人工金标。
- **“为什么不现场调模型？”** 主线是研究可复核，公共演示不应被密钥、限额和网络变成单点故障。
- **“这些 CTR 能代表平台吗？”** 不能；公开数字是虚构计算夹具，只证明口径和交互正确。

## 禁止表述

不说“证明某梗提升 CTR”、“预测爆款”、“已达到 0.85 F1”、“与番茄内部团队协作”、“独立从零搭建整个上游平台”。在真实实测表、样本和定义公开前，所有目标数字均只能称验收门槛。
