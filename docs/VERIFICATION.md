## 真实模型案例与报告

- 输入：1,285,824 bytes，435,393 个 NFC/LF 规范化 Unicode 码点，89 个编号章节、14,821 个段落行。
- 实际链路：19 个 gap-free 模型分块 → 152 条段落唯一逐字引文 → 作品级综合 8 节；正文引用其中 34 条不同证据，共 45 次引用。完整证据索引保留全部 152 条。
- 证据位置：包装材料 1 条、正文 139 条、番外 12 条；章节类别与偏移重新对原文检查。引文存在性通过，不代表整条复合判断的语义支持已经通过。
- 汇总在前两次调用中快速失败（exit code 1）；静态排查发现 Structured Outputs 不支持 `uniqueItems`。修复传输 Schema 后恢复成功，19 份 map 缓存全部复用，本轮只新增 1 次汇总模型调用。由于原始 stderr 未保存，不能把该根因推断写成已读取到的服务端错误。
- 产物：私有 `analysis.json`、`evidence-index.json`、`报告正文.md`、`HerLens_分析报告.html`、来源说明及渲染回执。报告区分正文与附加内容的时间线层级，对未发生状态和关系历史保留时态与证据边界。
- 最终 HTML 经 canonical renderer 验证：1440／390 宽度、静态图表、来源面板键盘交互通过；单文件可离线读取。没有 PPT 产物。
- AI 二次抽查与程序检查均不替代人工金标；面试使用前仍需熟悉作品的人复核关键结论。
- AI 二次审校抽查前 3 块和最后 3 块，共 48 条引文及相邻上下文，另核对最终摘要与关系／结局章节；未发现阻断性硬错误，但保留复合概括证据粒度、候选类别与弱职业线索等风险，不将这项有界检查外推成全文语义准确率。
- 本次实际使用提示词 1.0（已按原哈希冻结在私有目录）；它预设关系阶段和正文／番外等检查点，因此不是盲测。后续通用模板 1.1 改为条件化关系检查，明确亲情／友情／同事／无 CP，不要求男主或恋爱；新指纹不会误用旧缓存，非恋爱契约已回归。

## 实测中修复的问题

| 问题 | 程序修复与回归 |
| --- | --- |
| 两句普通正文被识别成章节 | 收紧“单位在前”标题边界并加反例测试；重新 benchmark 得到 89 章、73 个 6,000 码点以内的无缺口块 |
| 汇总 Schema 传输兼容性 | 逻辑 Schema 保留唯一性；传输 Schema 移除不支持项，由 Python 后验强校验；单测验证两层契约 |
| 失败后重试缺少历史 | 后续 runner 持久保留最多 20 条脱敏 attempt_history，记录 stage、固定错误码，不存原始 stderr／提示／凭据；恢复回归测试覆盖 |
| Windows 经典滚动条下报告横向溢出 | 仅修正官方 renderer 已知 top bar 宽度规则；不另建主题；桌面与手机验收通过 |

修复后结构性能记录为 `private-benchmarks/case-a-current.json`：三次中位数 522.274 ms、`tracemalloc` 峰值中位数 8,408,543 bytes。仅测解析／切分，不含模型推理。
