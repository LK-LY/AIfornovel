# ADR-0001：保留 React/Vite 前端，增加 FastAPI 本地分析后端

- **状态：** Accepted
- **日期：** 2026-09-22
- **决策范围：** HerLens P0

## 背景

仓库已有一个可用的 React / Vite / TypeScript 公共演示，完成了四个页面、证据侧栏、人工修订—重算状态和诚实空状态。P0 还需要本地持久化、幂等任务、精确证据验证、参数化 SQL、受限研究流程和多格式导出。

设计参考了 `novel-deconstructor` 的 React/FastAPI 分层和 `novel-analysis-agent` 的结构化 evidence 思路，但当前 HerLens 代码是独立实现，未合并两套上游流水线。

## 决策

1. 保留现有 React / Vite / TypeScript 前端和其视觉系统。
2. 在 `backend/herlens/` 增加单一 FastAPI 应用，业务路由统一使用 `/api/strategy`。
3. 用 SQLite 保存元数据、修订、运行状态和报告；私有原文与中间文件留在 Git 忽略的本地运行目录。
4. 保留两种显式模式：
   - `npm run dev`：公共只读 fixture 模式，不自动请求后端。
   - `npm run dev:local`：明确连接本地 FastAPI。
5. 模型接口只是服务端可选适配器。无模型时，导入、fixture 回放、SQL、证据、审核、导出和测试仍可运行。
6. 不引入自由行动多 Agent、任意 SQL、向量数据库或任意网络抓取。

## 理由

- 公共静态演示可以在无 Key、无网络模型、无私有数据的情况下完成三分钟演示。
- FastAPI + SQLite 足够支持单人、单项目的纵向切片，同时便于用类型约束、临时数据库和 HTTP 测试校验行为。
- 保留现有前端避免将时间花在重写已达到需求的展示层，把开发重心放在证据与数字正确性上。
- 模式分离给私有文本、服务端密钥和公开作品集一个可检查的边界。

## 后果

**正向：**

- 演示页可独立部署到 GitHub Pages，不包含服务端凭据。
- 前后端可围绕冻结的数据契约并行验收。
- 研究数字可由确定性程序复算，模型不需要“手算”。

**代价：**

- 需要维护 TypeScript 的 camelCase 界面形状与 Python 服务契约之间的映射。
- 只读演示中的交互是回放或浏览器会话状态，不能冒充已持久化的生产写入。
- SQLite 和本地文件不适用于多租户或公网服务；任何公网化需要新 ADR 与安全评审。

## 被否决的方案

- **完整 fork 并改造 `novel-deconstructor`：**会引入写作、知识图谱和其他非 P0 边界，加大回归面。
- **合并两个上游流水线：**功能重叠且契约不同，不利于证明 HerLens 自己的研究方法。
- **纯前端应用：**无法安全保存模型 Key，也不适合做可恢复任务和参数化 SQL。
- **首版上云的多用户 SaaS：**身份、授权、数据删除与秘钥管理成本超出求职演示的实际需要。

## 验证方式

- `npm run dev` 在后端未启动时仍可完成公共演示。
- `npm run dev:local` 仅在显式本地模式下请求 `/api/strategy`。
- 后端测试使用临时 SQLite，不需要凭据或网络。
- 本地在 Node.js 24 上构建静态页并运行领域测试，在 Python 3.13 上运行后端与基准工具测试；CI 仅保留为未启用的示例。
